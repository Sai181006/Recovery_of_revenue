# Submission checklist

## Reproducibility

- [ ] Fresh clone installs with documented Node version.
- [ ] `npm run release:check` passes.
- [ ] `npm start` produces an empty clean production-style data path; `npm run dev` produces the seeded demo.
- [ ] Primary and fixture fallback demos complete within the official time limit.

## External evidence

- [ ] Official brief and judging requirements linked and reviewed.
- [ ] Razorpay test-mode pending, recovered, and halted flows captured and redacted.
- [ ] Public HTTPS webhook and invalid-signature behavior demonstrated.
- [ ] Trusted recovery flow verified for the selected account.
- [ ] Live model evaluation completed or simulation clearly disclosed.
- [ ] Messaging simulation accepted or approved provider configured.

## Safety and claims

- [ ] No secrets, direct identifiers, payment credentials, or live keys in repository/assets.
- [ ] Critical release gate passes with zero duplicate outward actions.
- [ ] Screenshots, video, logs, and report are redacted.
- [ ] Synthetic outcomes are never described as observed or incremental revenue.
- [ ] Limitations and production-readiness caveats are visible.

## Submission assets

- [ ] Final project/team names and member details.
- [ ] Repository, deployed demo, video, slides, and architecture links.
- [ ] Demo script, setup instructions, test evidence, and fallback plan.
- [ ] Deadline/time-zone and final submission confirmation recorded.
